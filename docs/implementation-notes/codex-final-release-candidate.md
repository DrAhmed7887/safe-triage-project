## Phase 1 audit

The release surface is coherent for a Hospital Lite release candidate.

- Package scripts exist for standard build, Hospital Lite build, Capacitor sync,
  Hospital Lite Capacitor sync, Xcode open, and iOS run flows.
- `frontend/src/App.jsx` mode-gates Hospital Lite with `IS_HOSPITAL_LITE`, and
  bypasses `AuthProvider`, Firebase Auth, and the protected standard routes.
- `frontend/src/pages/HospitalLite/HospitalLitePage.jsx` owns the single-page
  clinical flow: entry, review, and handoff.
- Hospital Lite components include local clinician sign-in, demo presets, the
  triage form, suggested triage review, queue rail, handoff record, engine-source
  badge, and language toggle.
- `frontend/src/lib/triageClient.js` tries the canonical backend `/triage`
  endpoint first, then uses the browser fallback only on offline, timeout,
  network, HTTP, or parse failure.
- `frontend/src/lib/triageEngineOfflineFallback.js` is explicitly marked as a
  degraded-mode fallback. It reports `ai_used: false` and
  `engine_source: 'offline_js_fallback'`.
- Parity tests exist in `tests/parity/` and assert that the JS fallback must not
  under-triage relative to the canonical Python engine on critical fixtures.
- `frontend/capacitor.config.ts` uses `webDir: 'dist'` and no dev-server URL,
  so Capacitor packages bundled assets.
- `frontend/ios/` exists and contains the Xcode wrapper generated by Capacitor.
- Release docs exist for TestFlight / App Store checklist, metadata, privacy
  policy, and demo script.

Current support status from code inspection:

- Local Hospital Lite demo: supported.
- `hospital_lite` production build: supported by
  `npm --prefix frontend run build:hospital-lite`.
- Offline synthetic demo behavior: supported through the JS fallback and local
  queue / audit storage.
- No-real-PHI warning: present in the sticky amber Hospital Lite banner and demo
  preset heading.
- Safety-floor strip: present on the review card when floors apply.
- Pediatric NEWS2 caveat: present for patients under 16.
- Demo presets: five synthetic presets are present.
- Clinician confirmation flow: required; override requires a written reason.
- iOS sync / open scripts: present as `ios:sync:hospital-lite` and `ios:open`.

Release concerns carried forward:

- `webContentsDebuggingEnabled` is now `false` in
  `frontend/capacitor.config.ts` for TestFlight/App Store readiness. Flip it
  temporarily only for local Safari WKWebView inspection, then restore `false`.
- Bundle ID is currently `app.safetriage.hospitallite`. It is professional
  enough for local RC work, but the final App Store Connect bundle ID decision
  remains Ahmed's manual choice before the first upload.
- The privacy policy draft says the Hospital Lite build does not call cloud
  services. The code tries `http://localhost:8000/triage` first when online, then
  falls back locally. That is not a cloud call, but it must remain documented as
  optional local backend behavior.
